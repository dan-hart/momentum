## Existing capabilities and mobile requirements

The native iOS app is now explicitly requested through macOS parity. Its
[architecture and acceptance proposal](superpowers/specs/2026-09-16-ios-parity-design.md)
maps the rows below to native iOS behavior. Rows remain Planned until implementation
starts; inspecting source and writing a design do not verify an app.
The [iOS acceptance checklist](IOS-PARITY-CHECKLIST.md) expands those rows into
individual task actions, settings, native integrations and required evidence.

Unless a row says otherwise, mobile Planned means: expose the same Rust behavior
through native, accessible mobile UI; verify persistence, offline operation, and
platform interaction. It does not mean a mobile app or binding already exists.
